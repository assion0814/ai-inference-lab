# 06 · 传感器协议逆向与系统集成

在没有完整文档的情况下，把十轴 IMU 与离线语音模块接进 RK3588，并验证协议解析的正确性。

## 结论

- 还原 IMU 串口帧格式（`7E 23 LEN FUNC DATA CHK`）与 4 类自动返回帧；还原 I2C 寄存器映射
- **三重交叉验证**解析正确：四元数反算欧拉角与官方欧拉角帧完全一致；静止陀螺仪输出 (0,0,0)；四元数模长 0.9983
- 用**静止加速度模长反推量程**：2061 ÷ 2048 LSB/g ≈ 1.006 g → ±16 g
- 发现语音模块**实测帧格式与官方文档不符**（实为 `AA 55`，文档写 `AA FF`）
- 排查并解决：X11/KMSDRM 冲突、摄像头 YUYV→MJPG（720p 9→22 fps）、板端 NAT 转发、中文字体缺失

## 场景

Orange Pi 5 Plus（RK3588）+ 亚博智能三件套：USB 摄像头、CI1302 语音模块、十轴 IMU。

## 为什么「交叉验证」是这个项目的核心

协议逆向最容易犯的错是**「看起来对」**。所以每一项都找独立证据：

| 验证对象 | 独立证据 |
|---|---|
| 四元数解析正确 | 反算 roll/pitch/yaw 与官方欧拉角帧逐位比对 |
| 静止状态正确 | 陀螺仪三轴输出全 0、加速度模长 ≈1 g |
| 量程推断正确 | 用 1 g 对应的 LSB 反推，与寄存器默认值吻合 |
| 帧格式正确 | 串口抓帧与 I2C 读数双向比对 |

## 硬件与系统排障

| 问题 | 现象 | 解法 |
|---|---|---|
| X11 授权 | GUI 起不来 | xhost + KMSDRM 冲突排查 |
| 摄像头格式 | 720p 仅 9 fps | YUYV → MJPG，提升到 22 fps |
| 板子出网 | 无法访问外网 | iptables NAT + DNS 配置 |
| 中文字体 | 界面显示方块 | 安装中文字体 + 字体缓存 |

## 边界

- CI1302 语音模块的**程序源码未获取**（百度网盘非 VIP 限制 500 文件/次，该目录 5115 个文件）
- IMU 0x32 帧第一个 float 的物理含义未确认（疑似相对高度）
- 摄像头未接 RK3588 VPU 硬件解码，仅 22 fps
- 控制台的拍照/AI 按钮仍为占位
