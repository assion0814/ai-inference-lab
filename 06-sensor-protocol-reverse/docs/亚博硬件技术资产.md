## 一、★★ 百度网盘全自动下载（无 GUI，可复用到任何分享链接）

### 1.1 为什么需要这个

官网/淘宝资料全在百度网盘，而 **Linux 官方客户端只能 GUI 操作**，无法脚本化。
本机已有 `Xvfb + x11vnc + noVNC` 环境（`baidu-desktop.service`，浏览器访问 `http://<host>:6080/vnc.html`），
但 GUI 自动化极不稳定。**绕过方案：提取客户端 Cookie，直接调 Web API。**

### 1.2 提取 Cookie（关键：Linux 下是明文）

```python
import sqlite3, shutil
src = "/home/assion/.config/baidunetdisk/Cookies"     # Chromium cookies SQLite
shutil.copy2(src, "/tmp/bd_cookies.db")               # 复制避免锁
c = sqlite3.connect("file:/tmp/bd_cookies.db?mode=ro", uri=True)
rows = c.execute("SELECT host_key, name, value FROM cookies WHERE host_key LIKE '%baidu%' AND value != ''").fetchall()
# 构建 cookie 串：取 .pan.baidu.com / pan.baidu.com / .baidu.com / .pcs.baidu.com
```

**关键 cookie：`BDUSS`（登录态）、`STOKEN`、`BAIDUID`、`PANPSC`**
**Linux 下 `encrypted_value` 是空的（`enc=0`），`value` 字段直接是明文** —— 不需要 DPAPI/keyring 解密。

### 1.3 ★ 三个 API 坑（都踩过）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **① surl 格式** | `share/verify` 返回 `errno=105` | **surl 要去掉开头的「1」**：`https://pan.baidu.com/s/1ABC` → surl=`ABC`。但 `shorturlinfo` 反而要**完整** surl |
| **② 列表接口** | `/share/list` 返回 `errno=-9` | 用 **`/api/list`**，并带上 `shareid`+`uk` 参数 |
| **③ 鉴权 cookie** | 光带 BDUSS 列不出分享内容 | 必须把 verify 返回的 `randsk` 作为 **`BDCLND`** cookie 带上（URL 编码） |

### 1.4 完整流程（Python）

```python
# 1) 拿 shareid/uk（注意：用完整 surl）
GET https://pan.baidu.com/api/shorturlinfo?shorturl=<完整surl>&t=<ts>&channel=chunlei&web=1&app_id=250528&clienttype=0
  → {"shareid": 31728679342, "uk": 255089395780163, "errno": -9}   # errno=-9 但有数据，忽略

# 2) 验证提取码（注意：用去掉1的 surl）
POST https://pan.baidu.com/share/verify?surl=<去1surl>&t=<ts>&channel=chunlei&web=1&app_id=250528&clienttype=0
  data: pwd=<提取码>
  → {"errno": 0, "randsk": "LkXkliTlinXD0IXWbVesV%2BlMnn8s7MfM4GM34Hx7nPc%3D"}

# 3) 列分享内容（注意：用 /api/list + BDCLND cookie）
GET https://pan.baidu.com/api/list?dir=/&shareid=<>&uk=<>&t=<ts>&channel=chunlei&web=1&app_id=250528&clienttype=0
  Cookie: <原cookie>; BDCLND=<randsk>
  → {"errno": 0, "list": [{"fs_id":..., "server_filename":..., "isdir":...}]}

# 4) 转存（注意：sekey + BDCLND 都带）
POST https://pan.baidu.com/share/transfer?shareid=<>&from=<uk>&sekey=<randsk>&t=<ts>&channel=chunlei&web=1&app_id=250528&clienttype=0
  Cookie: <原cookie>; BDCLND=<randsk>
  data: fsidlist=[<fs_id>]&path=/目标目录
  → {"errno": 0, "extra": {"list": [{"to": "/目标目录/xxx"}]}}

# 5) 下载（dlink 会 302，必须 -L 跟随）
GET https://pan.baidu.com/api/filemetas?target=["/path"]&dlink=1&web=5&clienttype=0&channel=chunlei&app_id=250528&t=<ts>
  → {"errno": 0, "info": [{"dlink": "https://d.pcs.baidu.com/file/..."}]}
curl -sL -H "Cookie: <原cookie>" -H "User-Agent: <UA>" "<dlink>" -o out
```

### 1.5 ★ 非 VIP 的限制（实测，必须提前知道）

| 限制 | 数值 | 影响 |
|---|---|---|
| **转存文件数** | **500 个/次**（超级会员 20000）| 大目录（如 5115 文件）转存失败，errno=12 + `"show_msg":"转存文件数超限"` |
| **下载速度** | **~80 KB/s**（账号级，并发无解）| 实测 1/4/8/16 线程：78.8 / 106.6 / 71.8 / 29.4 KB/s，**并发反而更慢** |
| 单文件大小 | 无限制 | — |

**⇒ 策略：先转存小文件，大文件后台慢慢下；超过 500 文件的目标需要拆分或升 VIP。**

### 1.6 存储配额查询

```bash
GET https://pan.baidu.com/api/quota?checkfree=1&checkexpire=1
  → {"total": 1104880336896, "used": 677675188260, "free": ..., "errno": 0}
```
**注意：`free` 字段不可靠（返回的是 total），真实可用 = `total - used`。**

## 二、★★ 亚博十轴 IMU（官方协议，已验证）

### 2.1 串口协议

| 属性 | 值 |
|---|---|
| 设备 | `/dev/ttyUSB1`（CH340，VID:PID `1a86:7523`）|
| **波特率** | **115200** |
| 默认频率 | **25 Hz**（可设 10~100 Hz）|
| 实测 | 100 fps（4 种帧 × 25 Hz）|
| 固件版本 | 1.0.0 |

**帧格式：**
```
7E 23 LEN FUNC DATA... CHK
  ├ 包头1 0x7E
  ├ 包头2 0x23
  ├ LEN   = 总字节数 = 校验位下标 + 1
  ├ FUNC  = 功能字
  ├ DATA  = 小端
  └ CHK   = sum(包头1 .. 校验位前) & 0xFF
```

**自动返回帧（4 种）：**

| FUNC | LEN | payload | 解析 |
|---|---|---|---|
| **`0x04`** | 23 | 18 B | **9 × int16** = ACCEL XYZ + GYRO XYZ + MAG XYZ |
| **`0x16`** | 21 | 16 B | **4 × float32** = 四元数 `Q0(w), Q1(x), Q2(y), Q3(z)` |
| **`0x26`** | 17 | 12 B | **3 × float32** = 欧拉角 `ROLL, PITCH, YAW`（**弧度**）|
| **`0x32`** | 21 | 16 B | **4 × float32** = `[?, 温度°C, 气压Pa, 参考气压Pa]` |

**主动命令（逆向不出来的，官方文档才给）：**

| FUNC | 命令帧 | 功能 |
|---|---|---|
| `0x80` | `7E 23 07 80 01 00 29` | **请求固件版本号**（返回 `7E 23 08 01 <主><副><补丁> <chk>`）|
| `0x70` | `7E 23 07 70 <00\|01> 5F <chk>` | **校准 IMU**（陀螺仪+加速度计），参数1: 0=清除 1=开始 |
| `0x71` | `7E 23 07 71 <00\|01> 5F <chk>` | **校准磁力计** |
| `0x73` | `7E 23 07 73 <T_L> <T_H> 5F <chk>` | **校准温度**，温度 = `(T_H<<8)\|T_L` / 100 |
| `0x60` | `7E 23 07 60 <Hz> 5F <chk>` | **设置输出频率**（10~100 Hz）|
| `0x61` | `7E 23 07 61 <06\|09> 5F <chk>` | **设置算法类型**（六轴/九轴）|
| `0xA0` | `7E 23 07 A0 01 5F A8` | **重置用户数据** |

**命令构造示例（Python）：**
```python
def make_cmd(func, params=b""):
    HEAD1, HEAD2 = 0x7E, 0x23
    length = 4 + len(params) + 1          # 包头2 + LEN + FUNC + params + CHK
    frame = bytes([HEAD1, HEAD2, length, func]) + params
    return frame + bytes([sum(frame) & 0xFF])
```

### 2.2 I2C 协议（另一种接法）

| 属性 | 值 |
|---|---|
| 从机地址 | **`0x23`** |
| 时钟 | 100 kHz |
| 特性 | 支持连续读（地址自增）|

**寄存器映射（小端）：**

| 寄存器 | 名称 | 类型 |
|---|---|---|
| `0x01`-`0x03` | VERSION H/M/L | uint8 |
| `0x04`-`0x09` | ACCEL X/Y/Z | int16 |
| `0x0A`-`0x0F` | GYRO X/Y/Z | int16 |
| `0x10`-`0x15` | MAG X/Y/Z | int16 |
| `0x16`-`0x25` | QUAT W/X/Y/Z | float32 |
| `0x26`-`0x31` | EULER ROLL/PITCH/YAW | float32 |
| `0x32`-`0x35` | BARO_HEIGHT（相对高度）| float32 |
| `0x36`-`0x39` | BARO_TEMPERATURE | float32 |

### 2.3 ★ 交叉验证方法（判断协议解析对不对的标准）

**用四元数反算欧拉角，必须等于官方 0x26 帧的值：**

```python
def quat_to_euler(w, x, y, z):
    roll  = math.atan2(2*(w*x + y*z), 1 - 2*(x*x + y*y))
    pitch = math.asin(max(-1, min(1, 2*(w*y - z*x))))
    yaw   = math.atan2(2*(w*z + x*y), 1 - 2*(y*y + z*z))
    return roll, pitch, yaw   # 弧度
```

**实测验证：**
```
四元数反算: roll=-63.0° pitch=-27.5° yaw=31.9°
官方欧拉角: roll=-63.0° pitch=-27.5° yaw=31.9°   ✅ 完全一致
```

**再加两条佐证：**
- 静止时陀螺仪 `(0,0,0)` ✅
- 四元数模长 `0.9983 ≈ 1.0` ✅

### 2.4 量程推断（没有手册时的通用方法）

```
加速度静止模长应 = 1g
实测模长 = 2061
若 ±2g  (16384 LSB/g): 0.126 g ❌
若 ±8g  ( 4096 LSB/g): 0.503 g ❌
若 ±16g ( 2048 LSB/g): 1.006 g ✅
⇒ 量程 ±16g，2048 LSB/g
```

## 三、★★ CI1302 语音模块（协议已实机确认）

### 3.1 ★ 最关键的纠正：Type-C 就是双向数据串口

**早期误判（已推翻）：** 以为 Type-C 只供电不传数据，数据走 4-pin 排针。

**实测真相：** Type-C 通过 **CH340K** 芯片实现**双向串口**，TX 和 RX 都通！
- 设备 ID：`1a86:7522`（CH340K）
- TX 方向（主机→模块）：发播报命令，模块**有声音** ✅
- RX 方向（模块→主机）：说话后收到 `aa 55 00 04 fb` ✅

**官方 udev 规则（来自文档《1.环境搭建》）：**
```bash
KERNEL=="ttyUSB*",ATTRS{idVendor}=="1a86",ATTRS{idProduct}=="7522",MODE:="0777",SYMLINK+="myspeech"
```

### 3.2 串口参数

```
波特率: 115200（不是芯片手册说的 9600！中间有 STC8H 桥接）
数据位: 8 / 停止位: 1 / 校验: 无 / 流控: 无
```

### 3.3 ★★ 协议帧格式（官方确认 + 实机逐字节验证）

```
AA 55 | 功能 | ID | FB
  ├ AA 55  = 帧头（固定）★ 官方文档写 AA FF，实测是 AA 55
  ├ 功能   = 0x00 命令词（模块→主机） | 0xFF 播报语（主机→模块）
  ├ ID     = 数据 ID（十六进制）
  └ FB     = 帧尾（固定）
```

**发送协议 = 接收协议**（官方表格两列一致）。

**实测 vs 官方截图逐字节对上：**

| 场景 | 官方截图 | 我们实机 |
|---|---|---|
| 上电/唤醒 | `AA 55 03 00 FB` | `aa 55 03 00 fb` ✅ |
| 说「小车前进」 | `AA 55 00 04 FB` | `aa 55 00 04 fb` ✅ |
| 说「停车」 | `AA 55 00 01 FB` | `aa 55 00 01 fb` ✅ |
| 主动播报 | `SEND AA 55 FF 60 FB` | `aa 55 ff 04 fb` 发送有效 ✅ |

### 5.3 板子联网（NAT 转发）

**症状：** 板子 DNS 全失败、ping 8.8.8.8 不通，但网关（主机）可达。

**解法（主机侧）：**
```bash
# 1) 开 IP 转发
sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward=1" > /etc/sysctl.d/99-rk3588-nat.conf

# 2) NAT（出网卡 = 主机有外网的那个）
OUT=$(ip route get 8.8.8.8 | grep -oE 'dev [a-z0-9]+' | awk '{print $2}')
iptables -t nat -A POSTROUTING -s 192.168.66.0/24 -o $OUT -j MASQUERADE

# 3) 放行转发（ufw 的 FORWARD policy 可能是 DROP）
iptables -I FORWARD 1 -i enp2s0 -o $OUT -j ACCEPT
iptables -I FORWARD 1 -i $OUT -o enp2s0 -m state --state RELATED,ESTABLISHED -j ACCEPT
```

**板子侧：** `/etc/resolv.conf` 设 `nameserver 223.5.5.5`

## 六、★ 方法论陷阱（这轮踩的）

### 6.1 `pkill -f <pattern>` 会杀掉自己的 shell

**这个坑已经踩了 5 次。** 因为 `pkill -f` 匹配完整命令行，而你的 shell 命令行里就含有那个 pattern。

**正确做法：**
```bash
# ❌ 危险
pkill -f download.py

# ✅ 用 PID + 排除自己
for p in $(ps -eo pid,args | awk '$0 ~ /python.*download\.py/ && $0 !~ /awk/ {print $1}'); do
  [ "$p" != "$$" ] && kill -9 "$p"
done
```

### 6.2 Python `subprocess` 传空字符串参数会破坏命令

```python
# ❌ 空 resume="" 会被 curl 当成一个参数（可能是 URL）
subprocess.run(["curl", "-sL", "-o", out, resume, url])

# ✅ 只在需要时添加
cmd = ["curl", "-sL", "-o", out]
if resume:
    cmd.extend(["-C", "-"])
cmd.append(url)
```

### 6.3 百度 `share/list` 不是正确的列分享接口

`errno=-9` 会让人以为是权限/参数问题，实际是**接口选错了**，应该用 `/api/list`。

### 6.4 存储配额的 `free` 字段不可靠

`/api/quota` 返回的 `free` 等于 `total`，真实可用 = `total - used`。
