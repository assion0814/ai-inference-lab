## 一、★ 修复了两个阻塞性故障

### 1.1 网络连不上：又是 DHCP 被 ufw 丢了

**症状**：网口 `carrier=1`、2.5G 协商成功，但板子完全不发任何包（连 ARP 都不应答）。

**根因**（和上次 RKNN 项目一模一样的坑）：
1. 主机上 **dnsmasq 没在跑**（板子求 DHCP 没人应答）
2. **ufw 的 INPUT policy=DROP** 把 DHCP 包全丢了

**修复**：
```bash
# 启动 DHCP 服务
dnsmasq --interface=enp2s0 --dhcp-range=192.168.66.100,192.168.66.200,255.255.255.0,12h --port=0

# 放行 DHCP（关键！）
iptables -I INPUT 1 -i enp2s0 -p udp --dport 67 -j ACCEPT
iptables -I INPUT 1 -i enp2s0 -p udp --dport 68 -j ACCEPT
```

**结果**：板子立刻拿到 `192.168.66.129`（MAC `26:0d:5a:10:cc:a8`，hostname `orangepi5plus`）。

> **这个坑是第二次踩。写入纪律：直连板子拿不到 IP 时，先查 dnsmasq 是否在跑 + ufw 是否丢包，不要怀疑硬件。**

### 1.2 第二个串口消失：brltty 在抢 CH340

**症状**：`/dev/ttyUSB1` 出现几秒就消失，dmesg 显示：
```
ch341-uart ttyUSB1: ch341-uart converter now attached
usb 5-1.2: usbfs: interface 0 claimed by ch341 while 'brltty' sets config #1
ch341-uart ttyUSB1: now disconnected    ← 被抢走
```

**根因**：**`brltty`（盲文显示器守护进程）把 CH340/CH341 串口误认成盲文显示器**。
这是 Ubuntu/Debian 的经典 bug —— 而且它是 **udev 触发的**（`brltty-udev.service`），
光 `systemctl stop brltty` 不够，`pkill` 后插新设备又会被拉起来。

**修复**：
```bash
# 1. 杀掉所有 brltty 进程
for pid in $(pgrep -x brltty); do kill -9 $pid; done

# 2. 停 + mask 两个 unit
systemctl stop brltty.service brltty-udev.service
systemctl mask brltty.service brltty-udev.service

# 3. ★ 禁掉 udev 规则（关键，否则插新设备又抢）
sed -i 's/^/# disabled by agent /' /usr/lib/udev/rules.d/85-brltty.rules
udevadm control --reload-rules

# 4. 重新加载 ch341
modprobe -r ch341 && modprobe ch341
```

**结果**：`ttyUSB0` 和 `ttyUSB1` 都稳定了（等 10 秒不再消失）。

## 二、★ 十轴 IMU：协议完整破解

### 2.1 硬件识别

| 属性 | 值 |
|---|---|
| 设备节点 | **`/dev/ttyUSB1`**（CH340/CH341，VID:PID `1a86:7523`）|
| 波特率 | **115200**（不是官方文档说的 921600）|
| 帧率 | **100 fps**（4 种帧 × 25 Hz）|
| 接口 | USB（模块内置 USB-UART）|

### 2.2 ★ 协议格式（自己破解的）

```
┌──────┬──────┬──────┬──────┬─────────────┬──────┐
│ 0x7E │ 0x23 │ LEN  │ TYPE │   PAYLOAD   │ CHK  │
└──────┴──────┴──────┴──────┴─────────────┴──────┘
  帧头   固定   帧长   类型      数据       校验和

校验规则: CHK = (前面所有字节求和) & 0xFF   ← 已验证
```

**四种帧类型：**

| TYPE | LEN | PAYLOAD | 内容 |
|---|---|---|---|
| **`0x04`** | 23 | 18 字节 = **9 × int16** | `[acc_x, acc_y, acc_z, gyro_x, gyro_y, gyro_z, mag_x, mag_y, mag_z]` |
| **`0x16`** | 21 | 16 字节 = **4 × float32** | **四元数** `[w, x, y, z]`（模长恒为 1.0）|
| **`0x26`** | 17 | 12 字节 = **3 × float32** | **欧拉角** `[roll, pitch, yaw]`（弧度）|
| **`0x32`** | 21 | 16 字节 = **4 × float32** | 气压计 / 温度 `[?, 温度°C, 气压Pa, 气压Pa]` |

### 2.3 实测数据（静止状态）

```
【原始传感器】
  加速度 raw: X=   956 Y= -1670 Z=   737  (模长 2061)
  陀螺仪 raw: X=     0 Y=     0 Z=     0  (模长 0.0)   ← 静止，完美
  磁力计 raw: X=   814 Y=   975 Z=  -989  (模长 1615)

【四元数】 w=0.8236 x=-0.4820 y=-0.2925 z=0.0205  (模长 0.9983)

【模块自报欧拉角】 roll=-65.7° pitch=-27.5° yaw=20.9°
【由四元数反算】   roll=-65.7° pitch=-27.5° yaw=20.9°   ← 完全一致
```

**★ 交叉验证：用四元数反解出的欧拉角和模块自报值完全一致。**
**这证明协议解析和坐标定义都是对的。**

### 2.4 加速度量程推断

```
加速度模长 = 2061 (静止时应该 = 1g)
若 ±2g  (16384 LSB/g): 2061/16384 = 0.126 g  ❌
若 ±8g  ( 4096 LSB/g): 2061/4096  = 0.503 g  ❌
若 ±16g ( 2048 LSB/g): 2061/2048  = 1.006 g  ✅
```
**⇒ 模块配置在 ±16g 量程，2048 LSB/g。**

### 2.5 气压计

```
温度: 31.1 °C
气压: 101860 Pa (两次读数 101860 / 101883)
```
**⇒ 标准大气压 101325 Pa，当前读数偏高 0.5%，符合室内/低海拔环境。**

### 2.6 为什么不是官方说的 921600

亚博官方文档写「波特率 921600，回传率 200Hz」。
**实测：115200 baud，100 fps。**

可能原因：
1. 用户拿到的是**配置过的版本**（PC 软件可以改波特率）
2. 或这是**不同型号**（亚博有多款 10 轴模块）

**实测数据优先于文档。** 921600 下读到的是纯垃圾（只有 2 个唯一字节值，典型波特率不匹配）。

## 三、摄像头：完全可用

### 3.1 硬件识别

| 属性 | 值 |
|---|---|
| 设备 | **USB 2.0 Camera: HD USB Camera** |
| VID:PID | **`05a3:9230`**（ARC International）|
| 驱动 | `uvcvideo`（标准 UVC）|
| 节点 | `/dev/video0`（采集）、`/dev/video1`（metadata）|
| 接口 | **USB**（不是 MIPI CSI）|

### 3.2 支持的分辨率（实测枚举）

**MJPG（压缩）：**
| 分辨率 | 帧率 |
|---|---|
| 1920×1080 | 30 fps |
| 1280×720 | **60 fps** |
| 1280×1024 | 30 fps |
| 1024×768 | 30 fps |
| 800×600 | 60 fps |
| **640×480** | **120 fps** |

**YUYV（未压缩）：**
| 分辨率 | 帧率 |
|---|---|
| 1920×1080 | 6 fps |
| 1280×720 | 9 fps |
| 640×480 | 30 fps |

**⇒ 必须用 MJPG 才能到高帧率**（YUYV 因为 USB 2.0 带宽限制，1080p 只有 6 fps）。

### 3.3 实测结果

| 测试 | 结果 |
|---|---|
| 1080p MJPG 单帧截图 | ✅ 73 KB JPEG |
| 720p MJPG 10 帧 | ✅ 0.18 秒（≈55 fps）|
| 640×480 30 帧 | ✅ 0.38 秒（≈79 fps）|

**实测画面**：房间、置物架、灯、以及 RK3588 板子本身（画面旋转 90°，摄像头横装）。

### 3.4 RK3588 的 ISP 没被用上

```
dmesg: rkisp_hw fdcb0000.rkisp: max input:0x0@0fps
```
**⇒ RK3588 的硬件 ISP 存在但没有输入源**（因为摄像头是 USB，走不了 ISP）。

**如果换成 MIPI CSI 摄像头，可以用上：**
- 硬件 3A（自动曝光/白平衡）
- 硬件降噪、HDR
- **ISP 处理完全不占 CPU/NPU**
- 延迟从 30-60 ms 降到 <20 ms

## 五、语音唤醒模块：待确认

### 5.1 已排查的两个候选

| 候选 | 状态 | 说明 |
|---|---|---|
| **`/dev/ttyUSB0`** | 静默 | CH340 `1a86:7522`，**bInterfaceClass=255（vendor specific）**，各波特率 0 字节，AT 命令无响应 |
| **`/dev/ttyS9`** | 静默 | 板载 UART `febc0000.serial`（device-tree status=okay，是唯一启用的 UART），各波特率 0 字节 |

### 5.2 可能的情况

1. **SU-03T 类离线模块** —— 平时静默，只有听到唤醒词才输出字节
   - 需要用户实际说唤醒词
   - 接在 `ttyS9`（板载 UART）或 `ttyUSB0`（USB-UART）

2. **软件唤醒方案** —— 用板载 ES8388 麦克风 + 软件唤醒词检测
   - 这样就没有独立串口设备
   - 需要部署 openWakeWord / Porcupine

3. **模块没上电/没接好**

### 5.3 需要用户确认

- 模块型号是什么？（SU-03T / ReSpeaker / USB 麦克风 / 别的）
- 接在哪？（UART 的哪几根针 / USB / GPIO）
- 唤醒词是什么？

## 八、诚实边界

1. **语音模块没跑通** —— 两个候选串口都静默，需要用户确认型号和接线
2. **IMU 波特率与官方文档不符** —— 文档 921600/200Hz，实测 115200/100fps，原因未查明
3. **加速度量程是推断的** —— 用「静止时模长应等于 1g」反推 ±16g/2048LSB，没有用实验验证
4. **气压计两个值含义不明** —— `[?, 温度, 气压, 气压]`，第一个值和最后一个值的含义没确定
5. **摄像头只测了单帧和短序列** —— 没测长时间稳定性、没测真实帧率上限
6. **没用上 RK3588 ISP** —— 因为是 USB 摄像头，MIPI CSI 的优势没发挥
7. **没做 IMU 标定** —— 磁力计没做椭球拟合校准，yaw 可能有偏差
